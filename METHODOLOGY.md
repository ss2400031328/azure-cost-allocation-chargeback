# Azure Cost Allocation & Chargeback Methodology

## 1. Purpose

The objective of this model is to allocate Azure costs to departments
in a transparent, traceable and reconcilable manner.

Departments covered:

- CSE
- AIML
- IT
- Shared Platform

---

## 2. Cost Classification

Azure costs are classified into two categories.

### Direct Costs

Costs that can be directly associated with a department are charged
directly to that department.

Example:

- CSE resource → CSE
- AIML resource → AIML
- IT resource → IT

### Shared Costs

Costs generated by shared platform resources cannot be directly
assigned to one department.

These costs are distributed using an approved allocation driver.

---

## 3. Allocation Driver

For the demonstration model, the shared platform cost is allocated
using a usage-based allocation weight.

| Department | Allocation |
|------------|------------|
| CSE        | 50%        |
| AIML       | 30%        |
| IT         | 20%        |
| Total      | 100%       |

These percentages are demonstration allocation weights and are not
measured Azure usage.

---

## 4. Chargeback Calculation

For each department:

Chargeback =
Direct Cost + Allocated Shared Cost

For the demonstration dataset:

### CSE

Direct Cost = ₹400

Shared Allocation = ₹600 × 50% = ₹300

Chargeback = ₹700

### AIML

Direct Cost = ₹300

Shared Allocation = ₹600 × 30% = ₹180

Chargeback = ₹480

### IT

Direct Cost = ₹200

Shared Allocation = ₹600 × 20% = ₹120

Chargeback = ₹320

---

## 5. Reconciliation

The model verifies that the total departmental chargeback equals
the original cost.

Original Cost = ₹1,500

Chargeback Total = ₹1,500

Variance = ₹0

Reconciliation Status = PASS

---

## 6. Audit Trail

Every shared-cost allocation records:

- Shared resource
- Department
- Allocation driver
- Allocation percentage
- Allocated amount

This provides traceability for the chargeback calculation.

---

## 7. Governance

The allocation methodology should be documented and agreed upon
before production chargeback.

Changes to allocation percentages should be reviewed and recorded.

Department-level cost ownership is maintained through Azure resource
tags such as:

- department
- costCenter
- project
- environment
- owner

---

## 8. Data Source

The current implementation uses a synthetic demonstration cost
dataset because live Azure Cost Analysis usage data was not available
during development.

In a production implementation, cost data can be obtained from
Azure Cost Management exports or APIs.

---

## 9. Reporting

The model produces:

1. Department chargeback CSV
2. Shared-cost allocation audit CSV
3. Interactive Streamlit dashboard
4. Monthly chargeback PDF report

---

## 10. Reconciliation Control

A chargeback run is considered successful only when the variance
between source cost and allocated chargeback is within the configured
tolerance.

Current demonstration result:

PASS — ₹0 variance
